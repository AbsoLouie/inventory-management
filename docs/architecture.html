Data Flow

How a filter change on the page becomes updated numbers and charts.

  1. User changes a filter The four filters (Time Period, Warehouse, Category, Order Status) live in a singleton in useFilters.js, so every view shares the same state.
  2. View requests data The view calls getCurrentFilters() and passes the result to a method in api.js. Values equal to all are omitted from the query string.
  3. Request reaches FastAPI For example GET /api/orders?warehouse=Tokyo&month=Q1-2025. CORS middleware allows the cross-origin call from port 3000.
  4. In-memory filtering apply_filters matches warehouse, category (case-insensitive) and status; filter_by_month handles a single month or a quarter. The source lists are not mutated.
  5. Validation and response Pydantic response models validate the result and FastAPI serialises it to JSON. The dashboard endpoint also aggregates totals such as inventory value and low-stock count.
  6. UI updates The view stores raw data in refs (allOrders, inventoryItems) and derives charts and KPIs in computed properties, which re-render automatically.

Design Notes and Gaps

Things worth knowing before extending the system.

Design choices

  • No database: data resets on every backend restart.
  • Filtering is server-side, so the client only receives what it displays.
  • Inventory has no time dimension, so the month filter does not apply to it.
  • Pydantic models must be updated whenever the JSON shape changes.

Observed in the code

  • api.js defines task and purchase-order calls (/tasks, /purchase-orders), but no matching routes were found in main.py.
  • The API base URL is hard-coded to http://localhost:8001.
  • CORS allows all origins and there is no authentication, which suits local demos only.
  • views/Backlog.vue is neither routed nor imported; the Dashboard renders backlog data itself.
